# Module 1 Set Master: UI review and feature proposals, round 2 (chat 2)

Date: 2026-10-16. Reviewer: chat 2 (UI and features). Read only on code, nothing committed.
Environment: database `rof_m1_ui`, API on `localhost:3004`, code read from the main folder (uncommitted revamp). Roles driven: super_admin in the real browser; project_manager and read_only_viewer by API calls and by forcing the role in the page (`Auth.getUser`). Data is fake: 2 companies (one with a bank account), 2 projects, 4 document types, 1 dispatch, 304 cities in Haryana, test lists.
Viewports: desktop 1440 wide, laptop 800 wide, phone 375 wide; dark and light.
Already logged and not repeated here: M01-D001 to D006, M01-B001 to B009, M01-U001, M01-F001 to F004, DT-049 to DT-070, SM-F11 (several GSTIN per company), SM-F12 (import and export). Ideas that extend them say so.

## 1. Summary

The revamp is clean and consistent: one shell, one drawer pattern, one confirm dialog, no emoji, no gradients, no overflow inside the module at 375 wide, dark and light both render correctly, a 304 row city list paints in 7 ms. The weak points are (a) states that mislead the user (load failure looks like "no data", delete offered then refused, disabled delete reason never visible), (b) keyboard and screen reader gaps (no focus trap in the drawer or dialog, missing ARIA state), (c) light theme contrast on secondary text, and (d) the company screen, which is the most important one, has no sign of which company is active and mixes instant bank account saves into a form that has its own Save button.

Top 5 UI items: U2-001, U2-002, U2-003, U2-004, U2-005. Top 5 features: F2-001, F2-002, F2-003, F2-004, F2-005.

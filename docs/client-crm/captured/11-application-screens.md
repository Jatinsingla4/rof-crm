# Captured from the client CRM, part 11: more Application screens opened (nothing saved, no customer data kept)

- **Welcome Call** (Print Welcome): grid after Fetch: Broker, Sales Person, Mobile, Email, Customer Classification, Area, Avg Rate, Net Basic Price, Total Unit Cost, Paid Amount (%), Remark; icons for print, download, e-mail to the ticked rows; a call remark (200 chars) is added per customer.
- **Journal Entry** (moves money between two customers/units, popup flow): 1) Fetch by project / reg no / name / unit address, pick the customer to move money **from** (grid shows Reg No, Name, Unit Type, Unit Address, Paid Amount, Select); 2) a "Transfer To" row (same grid, pick the customer to receive); 3) form: Service Tax / GST = **Without Tax / With Manual Tax / With Auto Tax**, **Head Type** (All or one head), Amount, Adjustment Date, Remarks (max 1000); buttons CONTINUE, CLEAR. The journal needs approval later (Journal Report has Status, Approved By/Date, Approver Remarks).
- **Debit / Credit / Refund Note**: list per customer with Registration Date, Area, Amount, Service Tax, CGST, SGST, VAT, Extra Addon, Extra Addon S.Tax, Extra Addon GST, Interest, Net Amount, and per row the actions "Debit/Credit" and "Refund". The note form: customer strip (project, name, reg no, tower, address, booking date, plan, unit type, area, paid amount), Payment Type **Dr / Cr**, Service Tax **Without S.Tax/GST / With S.Tax/GST**, Payment Date, Amount, Remarks* ; buttons DEBIT (or CREDIT) and CLEAR.
- **Shift Units**: list Reg No, Name, Unit Type, Tower, Unit No, Plan Name, **Broker Paid Amount**, action Shift. The request form: customer strip (project, name, reg no, tower, unit, booking date, plan, unit type, area), then new Project Unit Type*, Tower*, Floor*, Unit No* (list + typed), Shifting Date*, **BSP at time of booking** (shown, e.g. 11,500: the customer's own rate), Document Upload, **Change Area Type: Increase Area / Final Area**, **Change Area Basic Price*** (new rate, current shown), Remarks*; SAVE makes a request (Unit Shift Report shows Pending / Approved / Rejected).
- **Cancel Allotment** list: Reg No, Name, Unit Address, Broker Company, Registration Date, Allotment Date, action Cancel.
- **Applicant History / Ledger** list (All / Registry toggle): Reg No, Name, Unit Address, Broker Company, Registration Date, Allotment Date and links **Statement**, **Ledger with Service Tax**, **Customer Ledger**, **Outstanding Amount**.
- **Agreement to Sale list** (Search Applicant): Reg No, Name, Unit Type, Unit Address, Registration Date, **Agreement Execute Date**, Mobile, **Registry Status**, Area, **Rate (differs per customer: 8,650 to 16,900 on the same unit type)**, Basic Price, Net Basic Price, Total Unit Cost, links "Agreement Date" and "RERA Agreement Letter".
- **"Customer Ledger" link = Payment Plan letter** ("To Whom It May Concern"): customer id, names of both applicants, address, date, project, tower, unit/plot no, floor, area, booking date, channel partner; a Basic Price table (Free Qty, Paid Qty, Rate per Sq. Ft., Amount, Total) with the total in words; "As agreed your payment plan is <plan>": table S.No, Installment Name, Installment Date (N/A for installments not yet raised), BSP, PLC, Other Charges, Amount, Total; "For <company>, Authorized Signatory"; declaration "I/We hereby solemnly confirm and affirm the above payment terms and schedule" with a signature line per allottee; note lines (IFMS, registry expenses, stamp duty and government levies extra; service tax extra with each installment; payments by draft / banker cheque in favour of the company payable at ...). Buttons E-MAIL, PRINT, DOWNLOAD, BACK, CLOSE, DOWNLOAD PDF.
Observation: the same unit type is sold at very different rates to different customers (booking rate is typed per customer); installment dates exist only for raised installments.

## Later in the same pass
- **Head Wise Cost** (HeadWiseCharge.aspx): filters Project*, Tower, Unit Type Group, Unit Type, Broker, Reg No, Name, Unit Address, Booking Date range. Grid in groups: *Customer details* (S.No, Reg No, Booking Date, Name, Unit Address, Dealer Name, Unit Type, Plan, Tower); *Cost detail* (Rate, **Actual Area, New Area**, Basic Price, Discount, Net Basic Price, PLC, Other Charge, IFMS, Total Unit Cost); then four blocks each with Amount, CGST, SGST, Total: *Basic Price*, *Total Unit Cost with Taxes*, *Payment Detail*, *Outstanding Amount*. "Actual Area" is the area at booking, "New Area" the area after an area change or unit shift; Basic Price = Rate x area (e.g. 11,500 x 510 = 58,65,000; other customers 12,250, 12,500, 15,500 on the same unit type).
- **User Define Letters** (PrintReport.aspx): project, tower, plan, **installment pick list shows a second, short set of names**: "On Booking (10.00)%, Inst1 (30.00)%, Inst2 (20.00)%, Inst3 (30.00)%, On Possession (10.00)%" for the same plan whose full names are "At the time of booking, Within 30 Days of Booking, On the Start of Excavation, ...". So every installment has a **long name** (stage text on letters) and a **short name** (screens and pick lists). The letter-type list was empty for this project (no user-defined letters set up).
- **Customer Wise Timely Discount**: the plan list is empty for this project (no plan has timely discount on, matching "Timely Discount: No" on all 10 plans).
- **GST invoicing screens** (Invoice Generation etc.): the project drop-down is empty for this login (stage, tower, plan also), so invoicing is not set up or not permitted for this user; their field lists are in part 2 only.
- **Set Extra Add On Charge** (project with data): grid S.No, Registration No, Booking Date, Name, Tower, Unit Type, Unit No, Plan, Amount, Action "Add | Edit" per customer; a customer's add-on lives on the customer row, set one by one or in bulk.
- **Applicant Addition/Deletion Process / Edit Customer Address** (EditRegistration_Approval.aspx): list Reg No, Name, Tower, Unit Address, Broker Company, Registration Date, Allotment Date, and the column **SEND UPDATION REQUEST: Edit**. The Edit opens a form with the booking's first-applicant fields (salutation, first / middle / last name, S/o etc., DOB, nationality, marital status, gender, children, passport, PAN, e-mail, then present / office / permanent address blocks with "Fill office / permanent address" ticks, pin, fax, country, state, city, mobile, phone). Saving **sends an update request** that has to be approved (this is the "Editing Status" workflow: Pending for approval / Unapproved / Approved / Rejected). In this edit form nationality offers only Resident / PIO / NRI (no OCI) and gender only Male / Female (the booking form has OCI and Transgender): their own inconsistency, do not copy.
- **Availability Sheet** (Tower Report, projectwisetower.aspx): one tile per tower showing "Tower T1 (Total: 117) (Available: 0) (Available: 0%)"; tile colour by share of units still available: 0-30% white, 30-50% orange, 50-80% blue-grey, 80-100% cream; print icon. ROF AMBLISS has towers T1 to T7 (Total 117 / 117 / 116 / 116 / 116 / 112 / 104; 2 units available in all).
- **Search Customer**: a row of tabs picks ONE search key (Reg. No., Unit No., First Name, Middle Name, Last Name, Date Of Birth, First Applicant PAN, Address, City, State, Email, Mobile No., Second Applicant, Second Applicant PAN); then one input and FETCH. No project is needed (searches all projects). Results come with "Print By Choice" columns (part 2).
- **Conveyance Deed Date** (MaintenanceAgreementDate.aspx): grid in two groups: *Customer details* (Reg No, Name, Tower, Floor, Unit No, Area) and *Customer dates* (Booking Date, Allotment Date, Registry Date, Agreement Date, RERA Agreement, **Conveyance Deed Date: a date box per row**), a tick box per row and a master tick; buttons SAVE and DELETE (bulk entry of the date for the ticked rows). Dates of the sale chain shown side by side: booking, allotment, registry, agreement, RERA agreement, conveyance deed.
